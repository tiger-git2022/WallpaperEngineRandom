# WallpaperEngineRandom（WE 加权轮播）

Wallpaper Engine 的托盘小工具：按每张壁纸的**添加时间**分档轮播。新壁纸每轮出现得多，老壁纸出现得少，
一轮播完保证每张都恰好出现了设定的次数。它不修改 Wallpaper Engine 本身，只通过 WE 自带的命令行接口切换壁纸。

## 下载

到 [Releases](../../releases) 下载最新的 `WallpaperEngineRandom-vX.Y.Z-win-x64.zip`，解压到一个固定文件夹
（例如 `C:\Tools\WERandom\`），双击 `WERandom.exe` 即可。

- 系统要求：Windows 10 / 11，自带的 .NET Framework 4.8，不需要另外安装运行库。
- 需要已经安装 Wallpaper Engine（Steam 版）。

## 开始 / 停止

- **开始**：双击 `WERandom.exe`。程序会缩到屏幕右下角托盘（可能藏在 ^ 里），第一次运行会自动弹出设置窗口。
- **停止**：右键托盘图标 →「退出」。
- **临时暂停**：右键托盘图标 →「暂停自动切换」，再点一次就继续。
- **开机自启**：在设置里勾选「开机自动启动」并保存；取消勾选并保存即取消。

程序所有文件（配置、日志、进度）都放在 exe 所在的文件夹里，删掉文件夹就彻底卸载。

## 第一次运行

1. 设置窗口里的 Wallpaper Engine 路径和创意工坊目录留空即可自动检测；在「壁纸预览」里能看到壁纸列表，就说明检测对了。
   检测不到时点「浏览…」手动选择。
2. 在权重档位里设置每档的次数（默认：≤2 个月 10 次、≤4 个月 5 次、≤6 个月 3 次、≤12 个月 1 次，更老的 1 次）。
3. 点「保存」。之后每 20 分钟（可以改）切换一张。
4. **把 Wallpaper Engine 自己播放列表的定时切换关掉**，否则两边会互相覆盖。

## 轮播模式

- **分组轮播（推荐）**：先放完最新一档，再放下一档。
- **混合轮播**：各档混在一起，均匀打散。
- **纯加权随机**：次数只作为相对概率。

## 计时规则

默认勾选「只在能看到桌面时计时」，计时器只在以下条件同时满足时才走：

- Wallpaper Engine 正在运行（退出 WE 计时就停；重新打开后接着算，并且会立刻切一张）
- 没有锁屏、没有睡眠
- 前台没有全屏程序（玩游戏、全屏看视频时暂停）
- （可选）键盘鼠标在最近 N 分钟内有操作，默认关闭

托盘图标的提示和右键菜单第一行会显示「下次切换约 X 分钟」或「计时暂停：原因」。

## 轮播是怎么工作的

- 一轮 = 所有壁纸次数之和。一轮播完，每张恰好出现了它的次数，然后自动开始下一轮。
- 一轮内部分布均匀：出现 10 次的壁纸每个“回合”都会来一次，不会集中在一段时间。
- 新订阅的壁纸会立刻按它的次数插进当前轮；取消订阅的会被剔除。
- 壁纸变老跨档时，会把它本轮剩余的次数调成「新次数 − 已播次数」，多出的部分均匀去掉。
- 改了权重想立刻生效：点「保存并重新开一轮」。

「添加时间」取壁纸文件夹的创建时间和程序第一次看到它的时间中较早的那个，记录在 `we_random.firstseen.json`，
以后 Steam 校验或更新文件也不会把老壁纸误判成新的。日期明显不对时，可以直接改这个文件。

## 文件说明

| 文件 | 用途 |
|---|---|
| `we_random.config.json` | 全部设置（与设置窗口是同一份，也可以手动改） |
| `we_random.queue.json` | 当前轮的剩余队列和进度；删掉 = 重新开一轮 |
| `we_random.firstseen.json` | 每张壁纸的添加时间 |
| `we_random.history.json` | 最近播放记录 |
| `we_random.log` | 日志，出问题先看这里（托盘菜单「查看日志」） |

## 常见问题

- **切换没反应**：先看日志。最常见的原因是 WE 自己的播放列表还在自动切换，把切换覆盖掉了；或者路径没有检测对。
- **托盘图标不见了**：可能被 Windows 收进了 ^ 里；或者程序没在运行，再双击一次 exe。
- **提示「程序已经在运行」**：托盘里已经有一个了，不用重复打开。

## 从源码编译

源码在 `windows/`（C#，.NET Framework 4.8，界面使用 [WPF-UI](https://github.com/lepoco/wpfui)）。

```powershell
dotnet build windows\WERandom.csproj -c Release
```

## 发布流程

在 [CHANGELOG.md](CHANGELOG.md) 顶部加一节 `## [X.Y.Z] - 日期`，合并（或推送）到 `main`。GitHub Actions 发现这个版本号还没有 `vX.Y.Z` 标签，就会自动编译，把打包好的 zip 发布到 Releases 并打上标签。最上面一节写成 `- 未发布` 时只编译、不发布。

也可以自己推送形如 `vX.Y.Z` 的 tag 来发布。

更新记录见 [CHANGELOG.md](CHANGELOG.md)。
